# 跨域代理助手（cross-origin-proxy）项目铁律

> 精简的 always-on 硬性规则。架构总览、关键文件速查、约定细节与常见陷阱见根目录 `AGENTS.md`。

1. **技术栈**：必须使用 WXT + Manifest V3 + Vue 3 + TypeScript + Element Plus + Vite + Vitest，均为最新稳定版；Element Plus 通过 `ElementPlusResolver` 按需引入，禁止整包导入，控制打包体积。
2. **代码质量**：保持可维护性、可扩展性、可复用性；重复逻辑、公共方法与组件必须抽离复用（纯函数入 `utils/`，响应式/生命周期入 `composables/`，界面入 `components/`）；复杂或安全关键代码遵循 JSDoc 规范。
3. **改动后自检**：完成功能或修复 bug 后必须做代码审核并执行自动化验证，禁止因优化或修复引入新问题、破坏存量功能与交互。
4. **格式化与静态检查**：统一使用 ESLint + Prettier + Stylelint；Stylelint 已启用 recess-order 属性排序，新增样式必须符合属性顺序规范。
5. **文件引入**：同级目录用 `./`，其它本地模块用 `@/`（已在 `wxt.config.ts`、`vitest.config.ts`、`tsconfig.json` 配置）；类型导入用 `import type`。
6. **日志**：运行时代码统一使用 `utils/logger.ts`，禁止裸用 `console`。已知例外：`console.warn`/`console.error` 为 ESLint 允许；MAIN-world 拦截器 `entrypoints/main-interceptor.content.ts` 必须自包含（不能 import logger/chrome），直接使用 console；`utils/logger.ts` 与 `scripts/` 豁免。
7. **提交前验证**：本仓库未配置 husky/lint-staged，提交前必须手动通过 `pnpm lint`、`pnpm format:check`、`pnpm lint:style`、`pnpm typecheck`、`pnpm test`；涉及入口/manifest/依赖/打包时另跑 `pnpm build`。CI 与发布共用的校验清单唯一收在 `.github/actions/verify`（加一项检查只改那里）；版本号只在 `package.json`（`wxt.config.ts` 不得再声明 `manifest.version`），发版是推 `v*` tag（见 `RELEASING.md`），仓库展示信息（About/website/topics/Pages 源）只能手动在 UI 填（见 `GITHUB.md`）。
8. **禁止规避规则**：新增代码必须通过 `pnpm lint`，禁止用宽泛 `eslint-disable`、`@ts-ignore` 或降低规则来绕过问题；确需例外仅限最小行范围并说明原因。
9. **国际化**：新增或修改可见文案必须同时补 `locales/zh_CN/` 与 `locales/en/` 对应命名空间（`common`/`options`/`popup`），中英 key 集保持一致；manifest 名称/描述改 `public/_locales/{zh_CN,en}/messages.json`；同步更新 `README.md`（中文主文档）与 `README.en.md`（英）（涉及 manifest 描述再改 `wxt.config.ts`）与 `docs/` 中英两页（中文在站点根 `index.html`、英文带 `en` 前缀，条目数必须对等，`tests/docs-consistency.test.ts` 已守卫）；用户可感知变化另需在 `CHANGELOG.md` 顶部记一条。
10. **优化边界**：大文件拆分、重复代码/组件/类型抽离、公共方法封装、变量提取等优化，必须在不改变原有功能与交互体验的前提下进行；一旦可能影响功能、交互、视觉、默认值、数据格式、权限或性能取舍，必须停下来说明并询问确认。
11. **改动评审重点**：评审改动不得影响存量功能与交互，尤其关注：popup/options 首屏体积、弹窗 `defineAsyncComponent` 异步加载、内容脚本非阻塞与 MAIN-world fallback 行为、DNR 与 SW 双通道分流一致性、Service Worker 可回收安全。
12. **安全**：把页面 DOM、导入文件（HAR/cURL/JSON）、runtime message、storage 数据都视为不可信输入，在边界处校验；状态修改类消息必须经 `isTrustedSender` 校验；遵循最小权限，不擅自扩大 `permissions`/`host_permissions`。注意：头名/CRLF 判据住在 `utils/headerValidation.ts`（表单保存侧与导入侧共用），状态码钳制与请求体上限由 `proxyHandler.ts` 导出，三者分别由 `tests/requestGuard.test.ts`、`tests/proxyResponseGuard.test.ts` 覆盖；导出脱敏（`utils/exportSanitize.ts`：`sanitizeExportData` 管配置、`sanitizeExportedLogs` 管 HAR，两者共用同一份分享模式判据）与搜索高亮（`utils/highlight.ts`，已无 `v-html`）各有单测；`messageRouter.ts` 的 `isTrustedSender`（为测试而导出）与它守的 gate 由 `tests/messageRouter.test.ts` 直接 import 真实现覆盖：状态修改类消息在不可信 sender 下必须同步拒绝、不触达存储、且 gate 先于参数校验；只读消息与 `PROXY_REQUEST` **不能**加 gate——内容脚本的 `sender.url` 就是页面 URL，加上去代理当场失效——页面来源的约束只能落在 `entrypoints/content.ts` 的桥接层（下发给页面的配置还要经 `toInterceptorConfig` 收窄，`targetOrigin` 挡不住同页脚本），不要试图靠扩大 `STATE_MUTATING_TYPES` 来「修」它。**读取类消息唯一的例外是 `messageRouter.ts` 的 `CREDENTIAL_READING_TYPES`（`GET_VARIABLES` 与 `GET_CONFIG_HISTORY`）**：判据是「页面永远不会问它、而回包是凭据或整包本地数据」，不是「它属于读取」，所以两者与状态修改类消息同样过 `isTrustedSender`；新增读取类消息时不要照它们加 gate，也别把这两个移出去。反面配对是 `INTERCEPTOR_STATS` / `GET_INTERCEPTOR_STATS`（页面自报的拦截活动）：写侧必须由内容脚本发出、读侧回包是六个整数（四个计数，加上 `updatedAt` 与作为交叉校验基准的 `swProxied`，见 `utils/types.ts` 的 `InterceptorStatsEntry`），两者都**必须留在门禁外**，`entrypoints/background/interceptorStats.ts` 只存内存（按 `(tabId, frameId)` 分账——内容脚本注入全部 frame，基线各 frame 各记一本才不误杀子 frame 的诚实自报；上限 `INTERCEPTOR_TAB_CACHE_SIZE` 按标签页计、读端跨 frame 求和、`tabs.onRemoved` 与文档重载清空），绝不写 `storage`、绝不参与任何判定分支；自报数可被同页脚本伪造，所以进 SW 后只有三道：字段合法性（四个非负有限数，任一非法即整包丢弃）、包内自洽（`proxied`/`fellBack` 不得超过 `intercepted`、`timedOut` 不得超过 `proxied`，四个数全 0 也丢——诚实的拦截器发不出这两种包，画出来却是一句自相矛盾的话）、与自己数的 `swProxied` 基线（低于即整包拒收）——最后一道是唯一不受页面影响的校验，除此之外不校验来源，同页脚本给出自洽的假数照样被采信，界面措辞永远写「页面自报」，五种状态（`noData`/`noReport`/`fellBack`/`timedOut`/`active`）各一句话、优先级是回退 > 超时 > 正常，判据只有 `utils/interceptorStats.ts` 一个出口。页面传来的 `ruleId` 也只是候选：`proxyHandler.ts` 的 `resolveSelectedRule` 复核（存在 + enabled + 仍匹配）后才采纳，绝不能拿它直接取规则执行。凭据真值只存 `STORAGE_KEYS.VARIABLES`，只在 SW 构造请求那一刻展开（`utils/variables.ts`，单轮、不递归），规则配置、导出文件、下发给页面 world 的配置、`STORAGE_KEYS.CONFIG_HISTORY` 里的配置恢复点与本地日志里都只有 `{{NAME}}` 引用；日志详情视图的头打码（`utils/headerMask.ts`）只发生在显示这一步，落盘与「复制为 cURL」仍是真实内容。导入预览（`utils/importPlan.ts` 的 `planImport`）必须与实际写入共用同一份判据（`ruleConflicts.ts` 的 `ruleMergeKey` ＋ `deduplicateRules`），另写一份差集就是「预览说 3 条、实际进 2 条」级别的谎报；配置恢复点只由替换式导入、加载快照、真正删掉东西的批量删除这三类整套替换落下，回退不动总开关；**「记录失败」绝不能变成「主操作失败」**，读不出旧账、新快照单份就越预算、写存储抛错（配额）这三种情形都只跳过这一份、旧账原样留着，只 `logger.warn`，也绝不能顺手把预算内的旧恢复点抹掉（读侧另有 `slice(0, MAX_CONFIG_HISTORY)` 兜住手改 storage）。设置页的凭据变量是**整表覆盖写**，`loadVariables` 失败时必须拦住下一次提交（`SettingsDialog.vue` 的 `variablesLoadFailed`），否则空列表 + 一次失焦保存就会抹掉用户已有凭据。
