一条规则，把 FAT 前端指到 UAT 后端——不改代码、不发版

跨域代理助手是一款 MIT 开源的 Chrome 扩展（Manifest V3），把页面发出的 API 请求代理到另一个后端环境。URL 重写、请求头与请求体改写、响应改写、Mock、延迟、阻断、WebSocket 转发，全部在浏览器里配置，全部只存在本机。

Manifest V3 无埋点无遥测 数据仅存本地 200 条规则 中英双语界面 MIT 开源
在 GitHub 查看源码 三步安装 看它怎么工作

Chrome 应用商店上架准备中，现阶段按下方方式从源码安装。

它省掉的是哪三件事

跨环境联调通常要付出三样代价之一：改后端、改每个项目的配置，或者在本地伪造一份构建。这个扩展把它们收敛成浏览器里的一条规则。

以最常见的「修复只在 UAT 上，我的 FAT 页面调不到」为例
不用扩展时 用一条规则时
改 devServer 代理表，然后重启本地服务。 填 https://fat-api.example.com/* → https://uat-api.example.com，保存即生效。
请后端把来源加进 Access-Control-Allow-Origin 再发一次版。 带任意高级能力的请求由扩展代发，页面侧不触发 CORS 校验。
在源码里硬写另一个环境的 token，还要记得改回来。 按规则注入请求头，联调完关掉这条规则即可。
接口还没写好，只能先在前端塞假数据。 在规则里 Mock 响应，业务代码一行不动。

工作原理：一套规则，两条通道

每条启用的规则在保存时被判定一次。只做 URL 重写的规则会被编译成 declarativeNetRequest 重定向，由浏览器网络栈直接处理，单个请求不跑任何 JS；能力更全的规则走扩展后台通道。 

页面 fetch / XHR / WebSocket
   |
   +-- 简单规则（仅 URL 重写）--> declarativeNetRequest 重定向
   |                              网络层完成转发，单请求零 JS 开销
   |
   +-- 复杂规则 --> 页面拦截器（main world）
                     +-> 桥接（isolated world）--> 后台发起请求
                                                   +-> 响应回传给页面

规则一旦带上下列任一项，就不再是「简单规则」

切到后台通道的准确条件
能力 网络层做不到的原因
请求头 / 请求体改写 替换请求体必须真正重发一次请求。
响应状态码 / 响应头 / JSON 字段改写 需要先读出响应，再重建一个响应。
Mock、延迟、阻断、重试 这些改变的是请求到底发不发生、什么时候发生。
HTTP 方法过滤 重定向规则无法按方法匹配。
查询参数注入 发生在重写之后，超出替换表达式能力。
WebSocket（ws:// / wss://） 重定向规则的资源类型里没有 websocket 这一项。
不以 * 结尾的通配符，或目标 URL 留空 替换表达式会静默丢掉末尾固定文本，或产出非法值。

拦截器一旦无法处理某个请求，就回退到页面原生的 fetch、XMLHttpRequest 或 WebSocket，请求照常发出。阻断规则是唯一的例外——被阻断的请求绝不回退。

功能清单

代理与改写

通配符、前缀、正则三种匹配方式。重写 URL，注入或替换请求头，替换请求体，改写响应状态码、响应头，以及按点分路径替换 JSON 字段（如 data.token）。

Mock / 延迟 / 阻断

不访问目标服务直接返回 JSON、文本、HTML 或 XML；注入 0–60000 毫秒延迟，用来验证骨架屏与超时分支；阻断请求，用来验证异常与离线兜底。

方法与参数控制

把规则限定在指定 HTTP 方法；在最终代理地址上追加或覆盖查询参数，例如 __env=uat 与灰度标识，而不必整段重写 URL。

WebSocket 转发

按 URL 重写转发 ws:// 与 wss:// 连接，让长连接和 REST 请求跟着同一个环境走。

规则管理

复制、批量启停、拖拽调整优先级、搜索筛选；环境轮换时用批量迁移目标域名，带逐条变更预览，避免误改。

日志与调试

查看方法、状态、耗时与命中统计；点开任意一条看到完整请求响应头与 body；一键复制为 cURL，或把抓包结果导出为标准 HAR 1.2。

导入与环境快照

导入 HAR 自动生成规则，粘贴 cURL 命令自动解析预填；把当前规则集存成命名环境快照，在 FAT / UAT / PROD 间一键切换。

界面与效率

中英文界面、6 套主题与浅色 / 深色 / 跟随系统、当前页面命中预演，快捷键 ⌘⇧P 切换、⌘N 新建、/ 搜索、Esc 关闭。

安装

1. 构建

git clone https://github.com/GH_OWNER/cross-origin-proxy
cd cross-origin-proxy
pnpm install
pnpm build

2. 加载

打开 chrome://extensions，开启右上角「开发者模式」，点「加载已解压的扩展程序」，选择 .output/chrome-mv3。

3. 第一条规则

  1. 在弹窗里打开代理总开关。
  2. 新建通配规则：https://fat-api.example.com/* → https://uat-api.example.com。
  3. 刷新页面，到请求日志里确认已被代理。

从源码构建需要 Node.js 20 及以上与 pnpm。开发调试执行 pnpm dev，端口 8899 热更新。

隐私与权限

所有数据都存在你本机的 chrome.storage.local。没有账号、没有统计埋点、没有自有远程服务，唯一的网络流量就是你要求代理的 API 流量；日志与导出文件也都在本地生成。查看完整隐私政策。

清单里声明的每一项权限，以及它的用途
权限 用途
storage 保存规则、请求日志、环境配置与偏好设置。
declarativeNetRequest 安装网络层重定向规则，让简单重写做到单请求零 JS 开销。
declarativeNetRequestFeedback 读取哪些重定向规则真正命中，用于日志抽屉里的命中统计。
alarms 代理期间维持后台脚本存活，并驱动自动关闭倒计时。
<all_urls> 站点权限 代理必须能在你的任意前端来源上工作，而目标环境通常是开发者自己的内网域名，无法事先枚举。

常见问题

浏览器的跨域代理到底是做什么的？

拦截页面发出的 API 请求并把它送到别处。开发里最常见的形态就是跨环境联调：让连着 A 后端的前端去调 B 环境的接口，不改代码、不重新构建，就能验证只存在于 UAT 的逻辑。

它能绕过 CORS 吗？

带任意高级能力的规则可以：请求由持有站点权限的扩展后台发出，页面拿到的是扩展构造的响应，不触发页面侧 CORS 校验。纯 URL 重写则被编译成网络层重定向，浏览器仍会校验 Access-Control-Allow-Origin。如果目标环境没放行你的来源，给规则加任意一项能力（最省事的是加个响应头改写），它就切到后台通道。

所有网站都能用吗？

内容脚本注入全部 http / https 页面，规则按请求 URL 匹配，内网系统、localhost 开发服务、预发域名都适用。chrome:// 页面、应用商店页与其他扩展页面是 Chrome 对所有扩展的统一限制，无法注入。

我的数据会被上传吗？

不会。规则、日志、环境配置与偏好都在本机 chrome.storage.local，没有统计埋点，也不连接任何自有服务。

和 devServer 代理、网关改配置有什么区别？

devServer 代理要按项目配、只覆盖指向本地服务的请求，同事也看不到你的配置；改网关或 CORS 需要后端发版。扩展装在浏览器里，一条规则对所有项目生效，还能改写响应与 Mock 数据，整套规则可导出 JSON 给团队。

为什么某条规则实际走的通道和我预期不一样？

因为不以 * 结尾的通配符、或目标地址留空的规则，无法在不做语义妥协的前提下表达成重定向，这类会被有意送到后台通道。用 URL 匹配预演功能输入任意地址，就能在依赖它之前先看清走的哪条通道。

有哪些限制？

规则 200 条、日志最近 500 条、请求体 10MB、延迟 0–60000 毫秒；Mock 与响应改写的状态码钳制在 200–599，否则前端构造不出合法的 Response。

扩展处理失败时会怎样？

拦截器回退到原生 fetch / XMLHttpRequest / WebSocket，请求照原样发出，页面不会因为扩展异常而中断。阻断规则是唯一例外：被阻断的请求绝不回退。

规则能分享给团队吗？

可以：导出 JSON、导出标准 HAR 1.2、粘贴 cURL 生成规则；环境配置快照还能把整套规则命名保存，在 FAT / UAT / PROD 间一键切换。

支持 Firefox 或 Edge 吗？

按 Chrome（Manifest V3）构建与验证。Edge 兼容 Chromium 扩展，同一份构建通常可用；Firefox 在 declarativeNetRequest 上的 MV3 支持存在差异，目前不作为支持目标。
